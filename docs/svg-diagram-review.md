# SVG 图示方案评审报告

> 评审对象：`docs/svg-diagram-plan.md`
> 评审视角：以帮助理解为唯一价值标准；以降低耦合为第一架构标准。
> 评审结论：**方向成立，方案需大幅修订。** 主要问题：生成器泛滥导致耦合面过大、与已有 19 个动画多处重复、以"按科补齐"为目标而非"理解增量"为目标。

## 一、评分

| 维度 | 评分 | 说明 |
|------|------|------|
| 架构方向（注册表 + 纯函数 + 声明式数据） | 8/10 | 方向正确，沿用 KB_ANIM 范式合理 |
| 耦合控制 | 4/10 | 9 个生成器 = 9 个数据契约，耦合面过大；自动布局引入行为耦合 |
| 范围控制 | 3/10 | "按科补齐全部高价值图"含大量与已有动画重复项，理解增量低 |
| 主题化/可测性 | 8/10 | CSS 变量 + 纯函数 + smoke 断言，设计合理 |

## 二、四个必须修复的问题（按优先级）

### P0-1 生成器从 9 个砍到 2 个

每个生成器都是一份数据契约（svgData schema）乘以所有使用它的图。生成器越多，改一处波及一片——这是本方案最大的耦合来源。逐个砍掉：

| 原生成器 | 处置 | 理由 |
|----------|------|------|
| gantt | 删 | processSchedule / pipeline 动画已覆盖调度甘特与流水线时空图 |
| matrix | 删 | 已有 table 块，矩阵/页表用表格更清楚 |
| funnel | 删 | 哈希散列可用通用 graph 表达，不单设 |
| layered | 删 | 封装层次、存储层次用 table/文字足够，理解增量低 |
| plot | 删（推迟） | 手写坐标轴成本高，408 复习边际价值低 |
| tree / stateMachine / graph | 合并为一个 `graph` | 三者本质相同：节点 + 边 + 标签 |
| memoryMap | 保留，更名 `bitfield` | 位段结构是文字/表格讲不清的唯一图型 |

**修订后只保留两个生成器：`graph` 与 `bitfield`。**

### P0-2 禁止自动布局，生成器做"哑巴渲染器"

原方案未明确布局责任。若 tree 生成器自动算坐标，则生成器逻辑一变，所有树的布局静默改变——生成器与全部图的内容形状发生行为耦合。

修订：坐标全部由作者在数据里写死，生成器只负责把 nodes 画成圆/框、edges 画成线/箭头、labels 画成文字。改样式只动 CSS，改布局只动数据，生成器本身几乎永不修改。这是"降低耦合第一标准"下最重要的单条决策。

### P0-3 以"理解增量"为准入门槛，先砍已有动画覆盖项

19 个已有动画覆盖：8 种排序、树遍历、图遍历、Huffman、KMP、页面置换、进程调度、滑动窗口、cache 映射、流水线、黎曼积分、矩阵乘法。**这些知识点一律不再配静态图**——重复不增值，还增加维护面。

准入三条件（同时满足才配图）：
1. 考试高频或理解关键；
2. 静态结构/状态/位段关系是理解本体，文字表格讲不清；
3. 无已有动画覆盖。

### P1-1 "禁止裸 SVG"一刀切过刚性

一次性图（如 CPU 数据通路）不该为它发明只被调用一次的生成器——"只用一次的抽象"是最差耦合。允许 raw SVG 逃生舱，但加三条铁律：
1. 颜色必须走 CSS 变量，禁写死色值；
2. 禁外部引用（字体/图片/脚本）；
3. 进 smoke 结构校验（合法 svg 标签、含 title/desc）。
全库 raw 图占比设上限（≤ 20%），超过即说明该抽象成生成器了。

## 三、逐科目"需要 / 不需要"清单

准入标准见 P0-3。"需要"按价值排序。

### 数据结构（ch4 树 / ch6 查找）

| 图 | 判定 | 理由 |
|----|------|------|
| AVL 四种旋转（LL/RR/LR/RL 转前转后对照） | **需要（最高优先）** | 纯静态结构变化对照，动画反而讲不清"为什么这样转"；考试必考 |
| BST 结构图（标注左小右大） | 需要 | 结构性质是本体；树遍历动画讲的是遍历过程，不重复 |
| 堆的"数组 ↔ 完全二叉树"双视图 | 需要 | heapSort 动画讲排序过程，不讲台积/下标对应；结构对应是理解堆的关键 |
| B 树 vs B+ 树结构对比 | 需要 | 考试高频，差异是静态结构差异（关键字分布/叶子链表） |
| 哈希：链地址 vs 开放定址对比 | 需要 | 静态对比一目了然，文字讲很绕 |
| 并查集路径压缩前后 | 可选 | 有价值但优先级低 |
| Huffman 树 / KMP 自动机 | **不需要** | 已有 huffman / kmp 动画 |

### 操作系统

| 图 | 判定 | 理由 |
|----|------|------|
| 进程五状态转换图 | **需要（最高优先）** | 经典静态图；processSchedule 动画是调度甘特，不是状态机 |
| 死锁资源分配图（有环 = 死锁直觉） | 需要 | "环"是视觉概念，文字讲不透 |
| 文件物理结构（索引节点多级索引） | 可选 | 静态结构，中等价值 |
| PV 生产者-消费者 / 读者-写者 | **不需要** | 代码是本体，图示反而稀释 |
| 页面置换 | **不需要** | 已有 pageReplace 动画 |

### 计组

| 图 | 判定 | 理由 |
|----|------|------|
| cache 主存地址位段（标记/行索引/块内偏移） | **需要（最高优先）** | 位段图是唯一讲清方式；cacheMap 动画讲映射过程不讲位段结构，不重复 |
| 指令格式位段（操作码/地址码） | 需要 | bitfield 复用，考试高频 |
| CPU 数据通路 | 可选（raw SVG） | 一次性图，走逃生舱 |
| 存储层次金字塔 | **不需要** | table 足够 |
| 流水线 | **不需要** | 已有 pipeline 动画 |

### 计网

| 图 | 判定 | 理由 |
|----|------|------|
| TCP 状态机 | **需要（最高优先）** | 高频、静态、无动画覆盖 |
| 三次握手 / 四次挥手时序图 | 需要 | 生命线时序；slidingWindow 动画讲窗口不讲握手 |
| CIDR 子网划分位段（网络位/主机位） | 需要 | bitfield 复用 |
| 封装层次 / ARP / DNS 流程 | **不需要** | 文字步骤足够，理解增量低 |

### 数学三科

**全部推迟。** plot 生成器成本高、理解增量低，且 riemann/matrixMul 动画已覆盖最有价值的两个点。

### 政治 / 英语

**不需要任何图。** 文本型学科，图示无理解增量。

## 四、修订后的架构（低耦合版）

```
data 文件                renderer.js              js/svg/generators.js
-----------              -------------            ----------------------
{ type:'diagram',   →    BlockRenderers.diagram  →  KB_SVG.graph(data)
  svgType:'graph',       （仅新增 1 个 case）        KB_SVG.bitfield(data)
  svgData:{...} }                                    （哑巴渲染器，无自动布局）
或
{ type:'diagram',
  svg:'<svg...>' }       （raw 逃生舱，一次性图专用，受三条铁律约束）
```

### 耦合矩阵

| 耦合点 | 机制 | 风险与控制 |
|--------|------|-----------|
| data ↔ 生成器 | 契约 = svgData schema | 生成器砍到 2 个，契约面最小；smoke 做 schema 校验，fail loudly |
| 生成器 ↔ CSS | 只输出语义类名（dg-node/dg-edge/dg-label） | 样式全部在 CSS，生成器不含色值 |
| renderer ↔ 图系统 | BlockRenderers 单 case | 改动面 5 行以内 |
| 图 ↔ 图 | 各自独立 svgData，无共享 | 零耦合 |
| 一次性图 ↔ 注册表 | raw 逃生舱 | 零耦合，占比上限 20% |
| 布局 ↔ 生成器 | 坐标写死在数据里 | 生成器永不重排，行为零耦合 |

### schema 校验（防静默破裂）

smoke.test.js 新增：遍历全部 diagram 块——
- `graph`：nodes 非空；每条 edge 的 from/to 必须存在于 nodes；坐标在 viewBox 内。
- `bitfield`：segs 非空；width 总和等于总位数。
- `raw`：以 `<svg` 开头、含 `viewBox`、含 `<title>`、无 `http` 引用、无写死 hex 色值。

## 五、修订后的落地路线

### Phase 1（一次做完，约 8-10 张图）
1. `js/svg/generators.js`：`graph` + `bitfield` 两个哑巴渲染器。
2. `renderer.js`：新增 diagram case。
3. `css/main.css`：dg-* 语义类。
4. smoke：schema 校验 + 渲染断言。
5. 嵌入图（按价值排序）：
   - DS：AVL 四旋转（4 张小图）、BST、堆双视图
   - OS：进程状态机、死锁资源分配图
   - 计组：cache 地址位段、指令格式位段
   - 计网：TCP 状态机

### Phase 2（按需）
- 计网：握手/挥手时序图（raw 或第三生成器，届时按使用点数定）
- DS：B/B+ 树对比、哈希对比
- 计网：CIDR 位段（bitfield 复用，成本近零）

### Phase 3（默认不做）
- 数学 plot、轻交互（hover/点击）。确有需要再单独立项。

## 六、与原方案的关键差异汇总

| 项 | 原方案 | 修订后 |
|----|--------|--------|
| 生成器数量 | 9 | 2 |
| 布局责任 | 未明确（隐含自动布局） | 数据写死坐标，生成器哑巴 |
| 一次性图 | 禁止裸 SVG | raw 逃生舱 + 三条铁律 |
| 图总量目标 | 按科补齐全部 | 准入三条件，Phase1 仅 8-10 张 |
| 与动画重复 | 未排查 | 已排除全部 19 个动画覆盖点 |
| 政治/英语/数学 | 数学列入 Phase 2 | 全部明确不配图 |
